# レイテンシ分析：bit幅増加時のレイテンシ減少現象

## データ概要

### Schoolbook乗算 (plot.py)
- Bit幅: [16, 32, 64, 128, 256]
- レイテンシ: [10.680, 3.000, 1.090, 0.610, 0.490] サイクル
- DSP使用数: [1, 4, 18, 50, 225]
- LUT使用数: [5465, 5470, 5488, 5738, 5595]

### Comba乗算 (plot_comba.py)
- Bit幅: [16, 32, 64, 128, 256]
- レイテンシ: [7.980, 3.180, 1.330, 1.100, 0.780] サイクル
- DSP使用数: [1, 4, 16, 50, 225]
- LUT使用数: [3633, 3972, 809, 5237, 7719]

## 観察される現象

**通常の期待**: bit幅が増えると計算量が増加し、レイテンシは増加する
**実際の結果**: bit幅が増えるとレイテンシが**減少**している

## レイテンシ減少の原因考察

### 1. パイプライン化の効果

実装コードを見ると、両方のアルゴリズムで `#pragma HLS PIPELINE II=1` が使用されています。

**パイプライン化の影響**:
- パイプライン化により、複数の演算が同時に実行される
- bit幅が増えると、より多くの演算が並列実行可能になる
- **固定オーバーヘッド**（パイプラインの初期化・終了）が相対的に小さくなる

**計算例**:
- 16bit: 演算数が少ない → パイプラインの初期化コストが相対的に大きい
- 256bit: 演算数が多い → パイプラインの初期化コストが相対的に小さい

### 2. リソース使用量の増加（並列化の向上）

DSP使用数が bit幅² に比例して増加している：
- 16bit: 1 DSP
- 32bit: 4 DSP (4倍)
- 64bit: 18 DSP (約4.5倍)
- 128bit: 50 DSP (約2.8倍)
- 256bit: 225 DSP (約4.5倍)

**解釈**:
- bit幅が増えると、より多くのDSPが使用可能になる
- より多くの乗算器が並列に動作する
- 結果として、**総レイテンシが減少**する

### 3. 固定オーバーヘッドの相対的減少

レイテンシの内訳を考えると：
```
総レイテンシ = 固定オーバーヘッド + 可変レイテンシ
```

**固定オーバーヘッド**:
- パイプラインの初期化
- データの読み込み/書き込み
- 制御ロジックの実行

**可変レイテンシ**:
- 実際の演算レイテンシ（パイプライン化によりほぼ一定）

bit幅が増えると：
- 固定オーバーヘッドはほぼ一定
- 可変レイテンシはパイプライン化によりほぼ一定
- **固定オーバーヘッドの相対的な割合が減少**

### 4. アルゴリズム固有の特性

#### Schoolbook乗算
- 二重ループ構造（i, j）
- 内側ループがパイプライン化されている
- bit幅が増えると、より多くの乗算が並列実行される

#### Comba乗算
- 対角ごとの和を計算
- 各対角がパイプライン化されている
- bit幅が増えると、より多くの対角が並列処理される

### 5. HLS合成最適化の効果

HLSツールは、bit幅が大きい場合に以下の最適化を適用する可能性がある：

1. **リソース共有の削減**: bit幅が大きいと、リソース共有のオーバーヘッドが大きくなるため、専用リソースを割り当てる
2. **ループ展開の増加**: より多くのループが展開され、並列性が向上
3. **メモリアクセスの最適化**: より大きなデータ幅でアクセスし、メモリバンド幅を効率的に使用

## 定量的分析

### レイテンシの減少率

**Schoolbook乗算**:
- 16→32bit: 71.9%減少 (10.680 → 3.000)
- 32→64bit: 63.7%減少 (3.000 → 1.090)
- 64→128bit: 44.0%減少 (1.090 → 0.610)
- 128→256bit: 19.7%減少 (0.610 → 0.490)

**Comba乗算**:
- 16→32bit: 60.2%減少 (7.980 → 3.180)
- 32→64bit: 58.2%減少 (3.180 → 1.330)
- 64→128bit: 17.3%減少 (1.330 → 1.100)
- 128→256bit: 29.1%減少 (1.100 → 0.780)

### 観察
- 小さいbit幅（16→32→64）では大幅な減少
- 大きいbit幅（128→256）では減少率が小さくなる
- これは、パイプライン化の効果が飽和している可能性を示唆

## 理論的モデル

レイテンシを以下のようにモデル化できる：

```
L(n) = L_fixed + L_var(n) / P(n)
```

ここで：
- `L(n)`: bit幅 n のレイテンシ
- `L_fixed`: 固定オーバーヘッド（約0.4-0.5サイクル）
- `L_var(n)`: 可変レイテンシ（n²に比例）
- `P(n)`: 並列度（DSP使用数に比例、約n²）

**結果**:
- `L_var(n) / P(n)` はほぼ一定
- `L_fixed` の相対的な割合が n が小さい時に大きい
- これが、n が大きい時にレイテンシが減少する理由

## 結論

レイテンシが減少する主な理由：

1. **パイプライン化の効果**: 固定オーバーヘッドが相対的に減少
2. **並列化の向上**: DSP使用数が増加し、より多くの演算が並列実行
3. **HLS最適化**: bit幅が大きい場合に、より積極的な最適化が適用される
4. **リソース効率**: より大きなbit幅で、リソースがより効率的に使用される

この現象は、**HLSによるハードウェア合成の特性**を示しており、ソフトウェア実装とは異なる挙動である。
