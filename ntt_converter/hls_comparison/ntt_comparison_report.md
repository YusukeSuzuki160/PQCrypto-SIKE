# NTT HLS 合成比較レポート

**ターゲットデバイス**: xcvu9p-flga2104-2-i (Vitis HLS 2024.2, target 10ns clock)

| 実装 | 説明 |
|------|------|
| **変換前** (`ntt_forward_orig`) | `%` ベースの mulmod / HLS プラグマなし |
| **旧変換後** (PIPELINE のみ) | `%` ベースのまま `#pragma HLS PIPELINE II=1` を付与しただけ |
| **新変換後** (本最適化) | Barrett リダクション + ブランチレス add/sub + 完全分割バッファ + 依存最適化 |

---

## なぜ「旧変換後」は速くならなかったか

`#pragma HLS PIPELINE II=1` を付けても II は 71 のまま（変換前の 69 とほぼ同じ）だった。
原因は **`mulmod` 内の `%` 演算**である。`%` は HLS では反復型除算器 `srem`
（レイテンシ約 68 サイクル）に合成され、これが乗算結果に必要なため
II=1 のパイプライン化が物理的に不可能だった。**プラグマだけでは無意味**で、
データパス側の改善が必須だった。

---

## 本最適化（ハードウェアアーキテクチャを考慮した変更）

### 1. Barrett リダクションで除算器を排除（最大の効果）
`a*b mod m` を **乗算・シフト・補正のみ** で計算する。
事前に `mu = floor(2^63 / m)` を求めておき（m はループ不変なので NTT 1 回につき 1 度だけ計算）、

```
q = (x * mu) >> 63        // x = a*b、x/m の近似
r = x - q*m               // 0 <= r < ~2m、最大 2 回の条件付き減算で確定
```

で reduction する。除算器 `srem`（~68 cyc）が消え、全段が乗算器・加算器のみになるため、
バタフライをパイプライン化できる。

### 2. ブランチレス addmod / submod
`if (r >= m) r -= m;` を算術マスク（`r - (m & -(r>=m))`）に置換し、
分岐によるスケジューリング阻害を排除。

### 3. 完全分割ローカルバッファ（ARRAY_PARTITION complete）
1 バタフライは `a` に 2 read + 2 write を行うが、BRAM は 2 ポートしかないため
そのままでは II≥2 が下限になる。先頭で BRAM からレジスタ配列へロードし
（`#pragma HLS ARRAY_PARTITION variable=buf complete`）、
任意の 2 要素を 1 サイクルで read/write 可能にして **II=1** を達成。

### 4. 偽の配列依存の排除（DEPENDENCE）— クロック周期の回復に必須
分割バッファを変数インデックスでアクセスすると、HLS は
「`buf[i+j+len]` への書き込みが次反復の読み出しと衝突するかもしれない」と
**保守的に偽の依存**を仮定し、Barrett の長い演算経路を 1 段（Depth=2）に押し込めて
しまった。その結果クロックが **23.4 ns**(Fmax 42.7 MHz)に劣化していた。

内側ループの各 `j` は互いに素なインデックス `(i+j, i+j+len)` にアクセスするため
反復間依存は実際には存在しない。これを

```cpp
#pragma HLS DEPENDENCE variable=buf type=inter dependent=false
```

で宣言すると、HLS が Barrett 経路を **5 段にパイプライン化**（Depth=5, II=1）でき、
クロックが **6.12 ns**(Fmax 163 MHz, 10ns 制約を満たす)まで回復した。

---

## まとめ

- **II 69 → 1**、実効スループット **389 ns → 6.12 ns/butterfly（約 63× 高速化）** を達成し、
  かつ **10 ns のクロック制約を満たす**（推定 6.12 ns）。
- 「PIPELINE を付けるだけ」では `%`(srem) がボトルネックで全く速くならない。
  **Barrett リダクション**でデータパスから除算器を除くことが本質的な改善点。
- 完全分割でメモリポート律速を解消し、**DEPENDENCE 宣言**で偽依存を外すことで
  II=1 と高 Fmax を両立させた。
- コストは LUT 2.3×・FF 2.1×・DSP 4→27 だが、デバイス利用率は最大でも 4% と十分小さい。
- 機能等価性は `verify_equiv.cpp` で確認済み（Barrett mulmod を全 mod で 200 万件 ×、
  n=256 フル NTT を実 NTT 素数で変換前実装とビット一致）。
