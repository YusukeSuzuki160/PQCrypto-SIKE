# 変換後モンゴメリ乗算器 アーキテクチャ図

**実装**: CIOS (Coarsely Integrated Operand Scanning) アルゴリズム  
**対象設定**: WORD_BITS=32, NWORDS=8 (256-bit 法)  
**最良結果**: 31 clk / 7.224 ns クロック / DSP×39

---

       (32bit×8)     (32bit×8)    (32bit×8)      (32bit)
           │              │             │              │
  ─────────┴──────────────┴─────────────┴──────────────┴─────────
  │                                                               │
  │                   mont_mul_top_param                          │
  │                  (MontOps_Param::mul)                         │

  │   │  │           C2: キャリー連鎖 (j=1→7)           │  │      │

## 図2: CIOS ステージ データパス（1 反復 i の内部、NWORDS=8）

```
                 b[i] (32bit, 外側ループカウンタ i の値)
                   │
       ┌───────────┴───────────────────────────────────────┐
       │             PP Stage (j=0..7 完全展開)              │
       │                                                     │
       │  t[0] ──►[+]◄── a[0]×b[i] ◄──[×]─ a[0]   0 ──►C1 │
       │           │                                  │      │
       │ (更新t[0]) │                                 ▼      │
       │           │         t[1] ──►[+]◄── a[1]×b[i] + C1  │
       │           │                   │                 │   │
       │           │        (更新t[1]) │                 ▼   │
       │           │                   │    t[2] + a[2]×b[i]+C1
       │          ...                 ...          ...       │
       │                                                     │
       │  t[6] ──►[+]◄── a[6]×b[i] + C1 ──► (更新t[6])     │
       │                                          │          │
       │  t[7] ──►[+]◄── a[7]×b[i] + C1 ──► (更新t[7])     │
       │                                          │→t[8],t[9]│
       │  (DSP 8個 × 32×32乗算)                              │
       └─────────────────────────────────────────────────────┘
                              │
                   ┌──────────▼──────────────┐
                   │       m 計算              │
                   │ m = t[0] × mprime & MASK │
                   │ (DSP 1個, mprime は定数)  │
                   └──────────┬──────────────┘
                              │  m (32bit)
       ┌───────────────────────┴────────────────────────────┐
       │             RED Stage (j=1..7 完全展開)             │
       │                                                    │
       │  新t[0] ◄──[+]◄── t[1] + m×mod[1] ◄──[×]─ mod[1] │
       │  (= 下位捨て)       │                          │    │
       │                   C2 ──────────────────────►  │    │
       │                              新t[1] ◄── t[2] + m×mod[2] + C2
       │                                   ...              │
       │  新t[6] ◄── t[7] + m×mod[7] + C2                  │
       │  新t[7] ◄── t[8] + C2 の繰り上がり                  │
       │                                                    │
       │  (DSP 7個 × 32×32乗算, 1サイクル以内の組合せ論理)   │
       └────────────────────────────────────────────────────┘
                 ↓
        t[0..7] 更新済み → 次の i=i+1 反復へ (II=2 サイクル後)
```

**II=2 の原因: ループ間データ依存**
```
   i=k 反復: t[0..7] を更新
                  │
                  │ (t[] の値を次の反復が読む: WAR 依存)
                  ▼
   i=k+1 反復: t[0..7] を読み取って再計算
```
この依存チェーンのスケジュールに最低 2 サイクル必要なため、HLS は II=2 を選択する。

## 図3: 条件付き減算 (Cond Sub) データパス

```
    t[0]  t[1]  t[2]  ...  t[7]   t[8]     mod[0..7]
      │     │     │           │     │           │
   ┌──┴─────┴─────┴───────────┴─────┴───────────┴──────┐
   │                  SUB_LOOP (j=0..7, UNROLL)          │
   │                                                      │
   │   u[0] = t[0] - mod[0] - 0                         │
   │                  │ borrow                           │
   │   u[1] = t[1] - mod[1] - borrow  ────────────►     │
   │   ...                              borrow チェーン   │
   │   u[7] = t[7] - mod[7] - borrow                    │
   │                  │ borrow (最終)                     │
   └──────────────────┼──────────────────────────────────┘
                      │
   ┌──────────────────▼──────────────────────────────────┐
   │            keep_t 計算                               │
   │   keep_t = (t[8]==0 AND borrow==1) ? 0xFFFFFFFF : 0 │
   │            ↑                                         │
   │         t[8] は CIOS 後に 0 ならば桁あふれなし        │
   └──────────────────┬──────────────────────────────────┘
                      │  keep_t (32bit, 全 1 or 全 0)
   ┌──────────────────▼──────────────────────────────────┐
   │            SEL_LOOP (j=0..7, UNROLL)                 │
   │                                                      │
   │   c[j] = (t[j] AND keep_t) OR (u[j] AND NOT keep_t) │
   │                                                      │
   │   keep_t=0xFFF..F (borrow発生) → c[j] = t[j]        │
   │   keep_t=0x000..0 (borrow無し) → c[j] = u[j]        │
   │                                                      │
   │   ※ 定数時間実行: if文なし → タイミングサイドチャネル防止 │
   └──────────────────┬──────────────────────────────────┘
                      │
                   c[0..7]
```

  i=0:    [S1──S2──S3──S4──S5──S6]
  i=1:            [S1──S2──S3──S4──S5──S6]
  i=2:                    [S1──S2──S3──S4──S5──S6]
  i=3:                            [S1──S2──S3──S4──S5──S6]

  i=5:                                            [S1──S2──S3──S4──S5──S6]

    Init:      ~  1 clk
    CIOS_LOOP: II×(N-1) + Depth = 2×7 + 6 = 20 clk  ← パイプライン

## 図5: 変換前 vs 変換後 アーキテクチャ比較

```
  ┌─────────────────────────────────┬─────────────────────────────────┐
  │      変換前 (mont_hls_orig)      │     変換後 (MontOps_Param)       │
  ├─────────────────────────────────┼─────────────────────────────────┤
  │ for (i=0..N-1)                  │ for (i=0..N-1)                  │
  │ {                               │ {                               │
  │   for (j=0..N-1) // pipeline   │   for (j=0..N-1) // UNROLL     │
  │     t[j] += a[j]*b[i]+C1       │     t[j] += a[j]*b[i]+C1       │
  │                                 │                                 │
  │   for (j=1..N-1) // pipeline   │   for (j=1..N-1) // UNROLL     │
  │     t[j-1] = t[j]+m*N[j]+C2   │     t[j-1] = t[j]+m*N[j]+C2   │
  │ }  ← 内側 pipeline             │ }  ← 外側 PIPELINE (II=2)      │
  │                                 │                                 │
  │ [実行時 nwords 変数]             │ [コンパイル時定数 NWORDS]        │
  │  → HLS は内側ループ展開不可      │  → HLS が内側ループ展開可能      │
  ├─────────────────────────────────┼─────────────────────────────────┤
  │ 乗算器: 1個 (時分割)             │ 乗算器: 16個 (並列)              │
  │ CIOS 1反復: 9 clk (内側8回)     │ CIOS 1反復: 2 clk (II=2)       │
  │ CIOS 全体: 9×8 = 72 clk        │ CIOS 全体: 2×7+6 = 20 clk      │
  ├─────────────────────────────────┼─────────────────────────────────┤
  │  合計: 70 clk                   │  合計: 31 clk  (2.26× 高速)    │
  │  DSP: 39  LUT: 3299             │  DSP: 39  LUT: 3436            │
  │  clk: 7.224 ns                  │  clk: 7.224 ns                 │
  └─────────────────────────────────┴─────────────────────────────────┘
```

## 図6: HLS pragma とハードウェア構造の対応

```
  C++ コード                         生成されるハードウェア
  ─────────────────────────────────────────────────────────────
  #pragma HLS ARRAY_PARTITION        t[0]..t[9] が独立したレジスタに分割
    variable=t complete dim=1        → 全要素への並列アクセスが可能

  INIT_LOOP: for (k=0..9)            9→1 サイクルに圧縮
    #pragma HLS UNROLL               (ループ展開 = 並列化)
    t[k] = 0

  CIOS_LOOP: for (i=0..7)            ステートマシン + パイプライン制御回路
    #pragma HLS PIPELINE             → II=2 サイクル毎に次の i を受け付ける
    #pragma HLS LOOP_TRIPCOUNT       → タイミング解析用ヒント (機能変更なし)

  PP_LOOP: for (j=0..7)              8個の 32×32 乗算器 + 加算器チェーン
    #pragma HLS UNROLL               を組合せ論理として展開
    t[j] += a[j]*b[i] + C1          (CIOS_LOOP の1パイプラインステージに含まれる)

  RED_LOOP: for (j=1..7)             7個の 32×32 乗算器 + 加算器チェーン
    #pragma HLS UNROLL               を組合せ論理として展開
    t[j-1] = t[j]+m*mod[j]+C2       (CIOS_LOOP の1パイプラインステージに含まれる)

  SUB_LOOP / SEL_LOOP                8個の減算器 + MUX
    #pragma HLS UNROLL               を並列組合せ論理として展開
```

## 図7: INNER_UNROLL パラメータによるアーキテクチャ変化 (NWORDS=8)

```
  INNER_UNROLL = 0 (折りたたみアーキテクチャ)
  ┌──────────────────────────────────────────────────────┐
  │  外側ループ: pipeline なし (ステートマシン)            │
  │  内側ループ: PIPELINE II=1  (j=0,1,...,7 を逐次処理)  │
  │                                                       │
  │   1つの乗算器 (DSP×1) を時分割で再利用               │
  │   PP: 8 サイクル → m 計算 → RED: 8 サイクル = 17 clk/外側反復 │
  │   合計: 17×8 ≈ 218 clk  DSP: 15個                    │
  └──────────────────────────────────────────────────────┘

  INNER_UNROLL = 2 (部分展開、最小有効展開)
  ┌──────────────────────────────────────────────────────┐
  │  外側ループ: PIPELINE II=2                            │
  │  内側ループ: UNROLL factor=2 → ループ展開×2           │
  │                                                       │
  │   乗算器 2×2 = 4 個 (PP 2個 + RED 2個)              │
  │   ただし HLS は carry チェーン解決のため実質同展開     │
  │   合計: 31 clk  DSP: 39個  ← FULL と同一結果         │
  └──────────────────────────────────────────────────────┘

  INNER_UNROLL = 8 = NWORDS (完全展開、デフォルト)
  ┌──────────────────────────────────────────────────────┐
  │  外側ループ: PIPELINE II=2                            │
  │  内側ループ: UNROLL (完全展開) → 組合せ論理            │
  │                                                       │
  │   PP:  乗算器 8個 並列 + キャリー連鎖加算器            │
  │   RED: 乗算器 8個 並列 + キャリー連鎖加算器            │
  │   計 16個の 32×32 乗算器が1パイプラインステージ内に     │
  │   合計: 31 clk  DSP: 39個                            │
  └──────────────────────────────────────────────────────┘

  INNER_UNROLL = 0 vs 2(以上): 核心的な違い
  ┌──────────────────────────────────────────────────────┐
  │  INNER=0: 外側 pipeline 不可   → 内側 j ループが律速  │
  │  INNER≥2: 外側 pipeline 可能  → 外側 i ループが律速   │
  │                                    ↑                  │
  │                         loop-carried dep の II=2 が限界│
  └──────────────────────────────────────────────────────┘
```
