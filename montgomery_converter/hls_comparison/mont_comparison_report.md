# モンゴメリ乗算 HLS 合成比較レポート

**ターゲットデバイス**: xcvu9p-flga2104-2-i (Vitis HLS 2024.2, 10ns clock)  
**トップ関数**: `mont_mul_top`（256 ビット法 = 32 ビット語 × 8）  
**変換前**: `mont_hls_orig.cpp` — ローカル配列 / パイプライン指示なし  
**変換後**: `mont_hls_converted.cpp` — `ARRAY_PARTITION` + `PIPELINE II=1`  

| 指標 | 変換前 | 変換後 |
|------|--------|--------|
| 推定クロック周期 | 7.224 ns | 7.224 ns |
| 推定 Fmax | 138.4 MHz | 138.4 MHz |
| レイテンシ max[clk] | 70 | 31 |
| レイテンシ max[abs] | 0.700 us | 0.310 us |
| 内側ループ Final II | 1 | 2 |
| 内側ループ Depth | 2 | 6 |
| LUT | 3299 | 3436 |
| FF | 2535 | 2305 |
| DSP | 39 | 39 |
| BRAM | 0 | 0 |

## 考察

- 変換後は作業配列の `ARRAY_PARTITION complete` で BRAM 2 ポート制約を解消
- 部分積/リダクション走査の内側ループを `PIPELINE II=1` で流す（Final II=1 達成）
- 最終補正は分岐レス `cond_sub`（定数時間）で制御パスを単純化
- 語ごとの積和は倍幅型（`__uint128`/`uint64`）経由で DSP にマップ

### 面積 / レイテンシのトレードオフ

- 変換前は語数が定数（`NWORDS=8`）のため HLS が全ループを完全展開し、低レイテンシ（70 clk）だが大きな資源（LUT 3299, DSP 39）を要する
- 変換後は実行時 `nwords` + `LOOP_TRIPCOUNT` で逐次パイプライン化されるため、レイテンシは増加（31 clk）する一方、LUT 3436（104%）・DSP 39（100%）へと資源を大幅削減
- すなわち変換は「面積最小・高 Fmax・乗算器再利用（折りたたみ）」志向。最小レイテンシを優先する場合は呼び出し側で `nwords` を定数化すれば変換後コードも完全展開され得る
