# 多倍長乗算ヘッダの最適化まとめ（Schoolbook / Comba / Karatsuba）

本書は `mpx_mul_converter` が生成する HLS 向け多倍長乗算ヘッダについて、
**アルゴリズムの内容**と**ハードウェアアーキテクチャ上の工夫点**を 1 本にまとめたもの。

- 対象: `include/mpx_packed.hpp`（default）, `include/mpx_packed_{16,32,64,128,256}bit.hpp`
  （ブロック学校式 / Comba）, `include/mpx_packed_karatsuba.hpp`
- 共通条件: `digit_t = uint64_t`, `nwords = 8`（512-bit × 512-bit）,
  Vitis HLS 2024.2, `xcvu9p-flga2104-2-i`, 10 ns
- 詳細な合成数値は `hls_comparison_results/*.md` を参照

---

## 0. 全体に共通する HLS 設計原則

すべての改善は次の「ハードウェアで何が生成されるか」を意識した置換に基づく。

| 原則 | 何を避けるか | どう書くか | 効果 |
|------|-------------|-----------|------|
| **連結 = 配線** | 桁が重複しないリムの `+=` 逐次加算（長いキャリーチェーン） | `ap_uint::range()` 代入で連結 | 加算器・依存を排除 |
| **UNROLL で組合せ化** | 配線に過ぎないループの `PIPELINE II=1`（N サイクル） | コンパイル時上限 + `#pragma HLS UNROLL` | レイテンシ N→0 |
| **可変長ループ排除** | データ依存 `while(carry)`（HLS レイテンシ不定 `?`） | 固定回数 + 末尾一括桁上げ | **確定レイテンシ化** |
| **可変シフタ排除** | 実行時シフト量 `x << (var)`（巨大バレルシフタ） | コンパイル時定数オフセット | LUT・CP 改善 |
| **アフィン添字で II=1** | `p/NB`, `p%NB`（依存距離が解析不能） | 明示的な入れ子 `for bi: for bj:` | パイプライン II=1 達成 |
| **乗算器共有** | 全積を並列乗算器で同時計算（DSP 爆発） | 単一乗算器を II=1 で時分割 | DSP 最小化 |
| **キャリーセーブ** | 各積ごとに桁上げを全幅伝搬 | 列アキュムレータに余裕ビットで吸収、末尾 1 回伝搬 | 依存短縮 → II=1 |
| **右サイズ幅** | 一律の超広幅アキュムレータ | 必要最小ビット幅を `constexpr` で算出 | FF/LUT 削減 |
| **W 非依存設計** | ヘッダ毎に Digit 幅を暗黙仮定 | `BW = max(BLOCK_BITS/W, 1)` 等で一般化 | 任意 W で正当 |

## 1. Schoolbook（学校式・ブロック）

### 1.1 アルゴリズム

オペランドを `BW` 語（= `BLOCK_BITS/W`）のブロックに分割し、各ブロック対の積を
桁位置に応じて足し合わせる古典的な学校式。

```
a = Σ_bi A[bi]·R^(bi·BW),  b = Σ_bj B[bj]·R^(bj·BW)    （R = 2^W）
a·b = Σ_{bi,bj} (A[bi]·B[bj]) · R^((bi+bj)·BW)
```

- ブロック幅 `BLOCK_BITS` が乗算器幅。細かいほど DSP 減・部分積数 `NB²` 増。
- `NB = ceil(nwords/BW)`。1 ブロック積は `2·BW` 語。

### 1.2 改善の経緯（3 段階）

| 版 | 方式 | 問題点 |
|----|------|--------|
| 旧 | 各積を `c[]` 配列へ逐次桁上げ + **可変長 `while(carry)`** | レイテンシ**不定 `?`**・配列 RMW 依存・W 不整合で数値破綻 |
| 中 | 全積を `prods[]` 保存 → **広幅加算木**で一括合成 | 確定化したが**全積保存で FF 爆発・広幅木で LUT 爆発** |
| **現** | **キャリーセーブ列加算**（積を保存せず即時加算） | — |

### 1.3 現行版（キャリーセーブ列加算）の工夫点

1. **積を保存しない**: ブロック積 `A[bi]·B[bj]`（`2·BW` 語）を、列アキュムレータ
   `col[(bi+bj)·BW + t]` へ**その場で加算**。`prods[]` 配列が不要 → FF 大幅削減。
2. **アフィン添字で II=1**: 積ループを明示的な入れ子 `for bi: for bj:` にする。
   `col` の添字 `(bi+bj)·BW+t` が `(bi,bj)` の**アフィン関数**になり、HLS が依存距離を
   解析して **II=1**（1 積/サイクル）を達成。`p/NB`・`p%NB` の div/mod は
   アフィン性を壊し II が悪化するため**使わない**（実測 II=3 → 81 cyc が 191 cyc に劣化）。
3. **キャリーセーブ**: 各列を `W+8` ビットにして桁上げを吸収（最大 `2·NB ≤ 16` 語の
   累算でも溢れない）。桁上げ伝搬は**末尾に 1 回だけ**（組合せ・アンロール）。
4. **乗算器共有**: 積ループは単一乗算器を II=1 で時分割 → DSP 最小（変換前の半分）。
5. **W 非依存**: `BW = max(BLOCK_BITS/W, 1)`。`BLOCK_BITS < W` は `BW=1` にクランプ。

### 1.4 結果（uint64, 512-bit）

| 構成 | レイテンシ | DSP | FF | LUT | CP |
|------|-----------|-----|-----|-----|-----|
| 変換前（手書き） | 97 | 32 | 2,223 | 3,901 | 6.724 ns |
| **schoolbook-64** | **81** | **16** | 2,509 | **2,613** | **6.040 ns** |
| schoolbook-128 | 34 | 50 | 3,410 | 2,975 | 6.523 ns |
| schoolbook-256 | 21 | 225 | 3,500 | 3,471 | 5.575 ns |
| default（全幅 1 乗算） | 12 | 900 | 2,074 | 601 | 4.326 ns |

- **`schoolbook-64` は変換前を速度・DSP・LUT・CP で上回る**（FF のみ +13%）。
- 中版比で sb-64 の FF 16,117→2,509（−84%）/ LUT 14,948→2,613（−83%）。

## 2. Comba（積和走査・MSW-first）

### 2.1 アルゴリズム

Comba は出力桁（対角 `d = i+j`）ごとに部分積を集める「積和走査」。SIKE 実装では
MSW-first で `t,u,v` の 3 語連結アキュムレータに逐次加算する形を取る。

```
for d: for {i+j=d}: (hi,lo)=a[i]·b[j]; v+=lo→u→t（桁上げ連鎖）; emit c[d]=v; (v,u,t)←(u,t,0)
```

### 2.2 工夫点（Schoolbook との共有）

- **変換先ヘッダは Schoolbook と同一**。Comba 変換元（MSW-first）も
  `mpx::PackedOps<...>` ブロックヘッダへ置換され、相違は `LSW_FIRST`（true/false）のみ。
- **MSW-first の反転はコスト 0**: 入出力の語順反転は `src = LSW_FIRST ? idx : nwords-1-idx`
  という**定数の添字付け替え**で表現され、HLS が配線へ畳み込む。
  → **Comba 変換後の合成結果は Schoolbook 変換後と完全一致**（オーバーヘッドなし）。
- したがって §1.3 のキャリーセーブ最適化がそのまま効く。

### 2.3 結果（uint64, 512-bit）

| 構成 | レイテンシ | DSP | FF | LUT |
|------|-----------|-----|-----|-----|
| 変換前（手書き Comba） | **122–220（可変）** | 32 | 629 | 1,233 |
| schoolbook-64（変換後） | **81（確定）** | **16** | 2,509 | 2,613 |
| default（変換後） | 12 | 900 | 2,074 | 601 |

- **Comba は変換の最大受益ケース**: 手書きの**可変レイテンシ 122–220** を
  三角ループ起因の不定性ごと解消し、**確定 81 cycle**＋DSP 半減＋CP 改善。
- 手書き Comba の `t,u,v`（3 語）は**面積最小**だが逐次・可変。変換後は II=1
  パイプライン化で速度・確定性を取る代わりに FF/LUT が増える
  （**面積 ↔ 速度・確定性のトレードオフ**）。

## 3. Karatsuba（非再帰・コンパイル時展開）

### 3.1 アルゴリズム

3 回の半長乗算で乗算回数を削減する分割統治法。
`a = Al + Ah·R^k`, `b = Bl + Bh·R^k`（`k = n_lo`）に対し:

```
z0 = Al·Bl
z2 = Ah·Bh
z1 = (Al+Ah)·(Bl+Bh)
a·b = z0 + (z1 - z0 - z2)·R^k + z2·R^(2k)
```

HLS では再帰が合成不可（HLS 214-139）なため、テンプレート `mul_sized<MaxN>` で
**コンパイル時に展開**して非再帰化する。

### 3.2 工夫点

1. **桁上げビット分解（正当性修正・最重要）**:
   中間和 `Al+Ah` は `half+1` 語になり得るが、旧実装は直接乗算器幅（`half` 語）に
   切り詰めて**桁上げを捨てており、全幅入力で数値破綻**していた（テストが小さい値
   だったため露見せず）。これを古典的分解で修正:
   ```
   Sa = sa_lo + ca·R^ns          (sa_lo は ns≤half 語、ca∈{0,1})
   Sa·Sb = sa_lo·sb_lo + (ca·sb_lo + cb·sa_lo)·R^ns + ca·cb·R^(2ns)
   ```
   → **3 乗算がすべて同一幅 `half` 語**になり、補正項は 1bit による条件加算
   （mux+加算）だけで**乗算器を増やさず**正当性を回復。単一乗算器の共有も保たれる。
2. **連結で部分積を再構成**: 旧版は `z0/z2/z1` を 1056-bit アキュムレータへ `+=` で
   逐次再構成し、長大なキャリーチェーンを 3 本生成していた。各リムは桁が重複しない
   ため `range` 代入（連結）に置換し依存を排除。
3. **桁あわせ加算を単一広幅加算器に**: `add_half` を `II=1` 逐次キャリーループから
   1 個のキャリー伝搬加算器へ集約。
4. **配線ループの UNROLL**: 半分割コピー・パック/アンパックを `PIPELINE II=1` から
   `UNROLL` 化（組合せ回路）。
5. **アキュムレータ幅の縮小**: 一律 1056-bit を必要最小幅へ。

### 3.3 結果（uint64, 512-bit）

| 構成 | 分割 | レイテンシ | DSP | FF | LUT |
|------|------|-----------|-----|-----|-----|
| flat（手書き平坦・参考） | 1 段 | 104–108 | 450 | 11,663 | 17,205 |
| **base4（変換後）** | 1 段 | **15** | 450 | **6,930** | **6,773** |
| base8（変換後） | 0 段（直接） | **14** | 900 | 2,080 | 629 |
| base2（変換後） | 2 段 | 17 | 250 | 10,967 | 17,172 |

- **base4 は手書き flat を全指標で凌駕** — レイテンシ **15 vs 104 cycle（7×）**、
  DSP は同値（450）、LUT/FF はおよそ半分。旧版のレイテンシは `PIPELINE II=1` の
  逐次ループが支配的で、組合せ回路化により残りは DSP 乗算器のパイプライン段数
  （14–17 cyc）のみとなった。
- 詳細は `hls_comparison_results/karatsuba_report.md`。

## 5. まとめ

1. **共通思想**: 「ループ＝逐次回路、連結＝配線、while＝不定レイテンシ」を意識し、
   配線で済む処理は組合せ化、桁上げはキャリーセーブで末尾集約、乗算器は共有して DSP 最小化。
2. **Schoolbook/Comba**: ブロックヘッダを共有し、キャリーセーブ列加算 + アフィン添字
   II=1 化で、**`schoolbook-64` が変換前を速度・DSP・LUT・CP で上回る**。分割ビット幅で
   DSP↔レイテンシを連続選択可能。
3. **Comba 固有**: MSW-first 反転はコスト 0。手書きの**可変レイテンシを確定化**する点が最大価値。
4. **Karatsuba**: 桁上げビット分解で**正当性を回復しつつ単一乗算器共有を維持**、
   連結・UNROLL で **flat 比 7× 高速化**。
5. すべて全幅乱数 + 端値で**数値一致を検証済み**、変換パイプライン（`mpx_auto_rewriter`）も通過。
